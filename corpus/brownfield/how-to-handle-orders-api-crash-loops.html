How to handle orders-api crash loops

Created by Sara Kim, last modified on 2026-03-16

Summary

orders-api 5.2 was deployed with a config map that no longer had PAYMENT_GATEWAY_URL. The app exits on start when that variable is missing, so every pod crash looped and no orders could be placed for 17 minutes.

What happened

After the orders-api 5.2 deploy every pod went into CrashLoopBackOff. The logs showed "config error: PAYMENT_GATEWAY_URL is not set" just before each exit. No orders could be created.

Why it happened

  • The deploy did not mount the new config map, so PAYMENT_GATEWAY_URL was missing and the app exited on start.
  • Neither CI nor the readiness probe checked for required config, so the bad revision reached every pod.

Follow-ups

  • Write SOP-DEPLOY-002 that reads the start up error before rolling back. (Sara Kim)
  • Fail CI when a required config key is missing. (Orders team)
  • Load config before the readiness probe reports ready. (Orders team)
  • Post every rollback in the deploy channel. (SRE team)
